How these numbers are made

1 · collect

cs papers from the July–August id-months, mirrored from Google's arXiv bucket — a large sample of those months, not all of them. 18,844 PDFs, text extracted locally, PDFs discarded.

2 · parse

arXiv ids pulled out of each reference list by pattern. 15,905 of the 18,844 papers we extracted text from yielded a usable list — 84%.

3 · count

One citation per (paper, target) pair. Self-citations dropped. The rank is a count; there is nothing else in it.

4 · index

The works on this page are the ones the agent can read. The page defines what is indexed, not the other way round.

What this is not. It is not a citation count, and it is not a census: it is a count over a sample of two months of arXiv cs, so it measures what these papers build on, not what is important overall. Of the papers we did collect, the 16% whose reference lists did not parse are missing entirely. Grouping papers into named themes is deliberately absent: on this data, two runs of the same clustering agree on only 43–61% of pairs, so any theme label would be a claim about our code rather than about the literature.
