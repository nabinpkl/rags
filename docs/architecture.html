Design spec companion · 2026-07-04

askRAG — agentic RAG over the arXiv corpus

A public corpus explorer where the agent is a side panel that feeds itself: it decides when to search, what to read, and when to compute — inside hard budgets, behind read-only tools, on a $20/month footprint. Every load-bearing decision below is deliberate and carries a written revisit trigger.

6,460 papers / 11.6 GB PDFs (2007–2026, cs.CL-heavy) FastAPI (uv) · Next.js static export SQLite + FTS5 · Chroma embedded Haiku 4.5, hand-built loop worst case ≤ $22/mo by construction
01

Runtime architecture

One flat-cost VPS. The browser talks to FastAPI for data and the agent stream; PDF bytes never touch our servers — the user's browser fetches them directly from arxiv.org at the version-pinned URL matching our extraction.

Fig. 1 — runtime. Teal = the agent path; amber = budget enforcement; rust = sandbox blast radius.

02

One agent turn (the loop is the product)

The harness never stuffs retrieved context. The model decides when to retrieve, iterates, and stops; the harness owns everything around that decision.

  1. budget gate — message, session, per-IP, and global-daily token caps checked before any model call. If the global cap has tripped, the turn is served as a replay of a recorded showcase trace instead of erroring.
  2. model call — Haiku 4.5 with prompt-cached system prompt + tool schemas. Streaming; every event mirrored to the browser timeline.
  3. tool dispatch — the model calls search_corpus (hybrid retrieval), query_metadata (SELECT-only SQL), read_paper (extracted text spans), run_python (sandboxed analytics), or drive_ui (enum-validated explorer actions). All read-only by construction.
  4. fencing — tool results re-enter the prompt wrapped as labeled untrusted corpus content. Paper text is the injection surface; the real defense is that a compromised agent has no harmful capability to invoke.
  5. context management — stale tool results evicted/summarized; hard step cap of ~8 tool calls per user message.
  6. answer — sanitized markdown (raw HTML disabled), citations verified server-side against real chunk ids before display; quotes capped per §6c. Trace persisted to traces.db with tokens, cost, latency.

05

Decision records — chosen, priced, and triggered

Fourteen records; each names its rejected alternatives and the condition under which it should change. Changing one without hitting its trigger is churn, not engineering.

D1

Agent feeds itself; harness never stuffs context

Retrieval is a tool the model calls. Multi-hop is the demo; the harness owns budgets, eviction, stop conditions.

Revisit — >30% of eval questions are single-hop and cost binds → add a router.
D2

Hand-built loop on the raw Anthropic API

~200 lines we own. Every hardening claim points at a line we wrote — no framework between us and the API.

Revisit — becomes a product (adopt the SDK) or the loop grows past ~500 lines.
D3

Haiku 4.5 live; strong models offline only

$0.02–0.08 per agentic message with caching. Strong models draft the golden set and judge evals.

Revisit — evals embarrass it on >20% of the golden set, or prices drop.
D4

SQLite + FTS5 and embedded Chroma — no DB server

Two embedded stores, shared chunk ids, read-only in prod. Right-sized: a DB server buys nothing at 100k chunks.

Revisit — ~1M chunks, p95 >300 ms, or prod writes → pgvector (deferred, not rejected).
D5

API embeddings: text-embedding-3-small @512d

~$2 one-time for ~100M tokens; re-embedding is trivial money, which keeps eval-driven chunking changes honest.

Revisit — query spend >$5/mo, model deprecated, or a local model wins on evals.
D6

PyMuPDF4LLM extraction with a recorded skip list

CPU-fast, good on born-digital LaTeX prose. Known floor: tables and math retrieve poorly — measured, not hidden.

Revisit — v2 table-computation feature, or evals show extraction dominates failures.
D7

Section-aware ~1k-token chunks, page-anchored

Never cross section boundaries; every chunk carries (paper, section, pages) so citations land on the real page.

Revisit — recall plateaus and error analysis blames boundaries → sweep as an eval experiment.
D8

Hybrid: vector + BM25 → RRF; rerank eval-gated

BM25 catches acronyms and names embeddings miss. Every stage must pay rent on the eval set to ship.

Revisit — a leg contributes nothing (drop it, publish that) or rerank's margin pays its latency.
D9

Version-pinned arXiv embeds; we never serve PDFs

iframe of arxiv.org/pdf/<id><vN> — validated: no framing headers, #page=N works, old versions serve forever. Skew dead by construction.

Revisit — arXiv adds framing headers → PDF.js direct fetch (CORS-verified) → excerpts + link out.
D10

Fresh no-network Docker container per execution

Sandbox exists for corpus analytics. No egress + read-only public data + nothing persisted = the whole isolation story.

Revisit — any private/writable data in reach → gVisor minimum; cold starts hurt → warm pool.
D11

Free, anonymous, budget-capped; degrades to replays

Layered token caps end at a $0.50/day global ceiling. When it trips, the panel replays recorded traces — a demo, not an error page.

Revisit — real traffic exhausts the cap regularly → raise it or add BYO-key mode.
D12

Frozen corpus snapshot in prod, dated in the footer

Live updates would drag the ingest chain onto the VPS and break the read-only posture for one sentence of honesty.

Revisit — refresh cadence exceeds monthly → build the pipeline as the next portfolio chapter.
D13

FastAPI (uv) + Next.js static export on one VPS

Flat cost is the only hosting where a public agentic endpoint can't surprise-bill. SSE, not WebSockets. No Node in prod.

Revisit — a real SSR need appears, or sustained usage outgrows one box.
D14

Eval harness ships in v1 and gates retrieval decisions

~50 hand-verified golden QA pairs; recall@k + MRR per config; LLM-judged faithfulness. The README quotes the table.

Revisit — two configs within noise on a decision that matters → grow the set until it discriminates.
06

Threat model & content posture

Assets: the API budget, availability, visitors' browsers, the box. Not data confidentiality — everything on the box is public. The defense thesis: an injected agent should have nothing harmful to do.

The cap cascade: per-message tokens → per-session (~15 messages) → per-IP daily → global $0.50/day. Past the last gate the site doesn't die — the agent panel switches to recorded showcase replays with a banner. Denial-of-wallet is capped; denial-of-demo is impossible.
08

Build order — risk first, demoable at every exit

  1. ingest — repo reorg (collector/, corpus/), extract → chunk → embed → indexes; license + version backfill. Exit: corpus queryable via SQLite and Chroma.
  2. retrieval + evals — hybrid search + golden set + just eval. Exit: committed eval table justifying D7/D8.
  3. agent loop (CLI) — loop + all tools except sandbox, driven from a terminal REPL; traces from day one. Exit: multi-hop answer with verified citations in the terminal.
  4. web app — explorer, split viewer (D9 ladder tested), agent panel with SSE timeline + cost badge. Exit: full demo locally.
  5. sandbox — container + run_python + chart rendering. Exit: the venue-rigor trend plot works end-to-end.
  6. hardening + deploy — budget layers, replay mode, VPS + Caddy + Cloudflare, backups; notify arXiv. Exit: public URL, caps verified by attacking it ourselves.
  7. write-up — decision records, eval results, threat model, "what changes at 10×". Exit: the README is the portfolio piece.
